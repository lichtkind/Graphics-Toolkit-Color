=head1 NAME

Graphics::Toolkit::Color::Manual::Calculation - reference of single color calculation methods

=head1 SYNOPSIS

This L<manual|Graphics::Toolkit::Color::Manual> page contains the most
detailed description of the fourteen methods that produce a GTC color object
which in some fashion is related to the current one (caller or invocant): 
L</lighten>, L</darken>, L</lightness>,
L</saturate>, L</desaturate>, L</saturation>, L</derive>,
L</invert>, L</apply>, L</random>
L</tint>, L</tone>, L</shade> and L</mix>.
Because caller and result are GTC objects, chaining like this is possible:

    $color->derive( set => {saturation => 5} )->invert->mix( to => 'green' );

Every L<parameter|Graphics::Toolkit::Color::Manual::Argument> and important 
parameter combination will be explained in the dedicated chapter of a method,
but the first few paragraphs will explain what all methods have in common,
like the fact that they might trigger an L<error|Graphics::Toolkit::Color::Manual::Error>,
if arguments are not used as described here.


=head1 METHODS

There are two ways how one might categorize these 14 methods: by complexity or signature.
The first way would be to differentiate between the few complex and powerful low level methods
on the one hand and the many high level methods that have less power and less arguments on the other.
The latter are also called: "designer API", since they cater to a usage designers prefer:
methods with a clear name that fits its single purpose well. 
These methods are L</lighten>, L</darken>, L</lightness>,
L</saturate>, L</desaturate>, L</saturation>, L</tint>, L</tone>, L</shade>. All their functionality
can be achieved without any effort by using L</derive> and L</mix>. With some extra math sprinkled in -
the same holds true for L</invert>, L</random> and some might say even L</mix>.
So strictly speaking programmers would just need L</apply> and L</derive>,
but luckily this library is not only about functionality but also convenience.

The methods can also be divided into three groups, just by looking
at their signature. The first seven methods: L</lighten>, L</darken>, 
L</saturate>, L</desaturate>, L</tint>, L</tone> and L</shade>
accept beside C<in> and C<raw> also the argument 
L<by|Graphics::Toolkit::Color::Manual::Argument/by> (0..1),
which is required and the default argument there.
Default argument refers to the habit of all GTC methods to accept
named arguments or one sole positional argument which is a mere shortcut
for providing the most important, named argument, the default argument.

The second group consists of: L</lightness> and L</saturation>, which
additionally accept L<set|Graphics::Toolkit::Color::Manual::Argument/set> (number)
and L<multiply|Graphics::Toolkit::Color::Manual::Argument/multiply> (number).
For them C<set> is the default argument but none is required.
L</derive> is very similar, but with more powerful C<set>, C<multiply> 
and C<by> arguments and it additionally accepts a 
L<Graphics::Toolkit::Color::Manual::Argument/range> argument.

The third group consists of the methods: L</apply>, L</random>, 
L</mix> and L</invert> which do not fit into a simple pattern. 

All fourteen color calculation methods have in common that they accept the arguments 
L<in|Graphics::Toolkit::Color::Manual::Argument/in> (color space name) and 
L<raw|Graphics::Toolkit::Color::Manual::Argument/raw> (pseudo bool).
C<in> sets the color space the operation is computed in, which in most 
cases defaults to the perceptually uniform 
L<OKHSL|Graphics::Toolkit::Color::Manual::Space/OKHSL> space.
Only L</tint>, L</tone>, L</shade>, L<mix> and L<random> default to
L<OKLAB|Graphics::Toolkit::Color::Manual::Space/OKLAB>
for more meaningful results and L</tone_curve> defaults to 
L<LinearRGB|Graphics::Toolkit::Color::Manual::Space/LinearRGB> since 
this is most likely the space you want to apply a gamma value to.
The selection of color spaces is restricted for some methods, that rely
on the existence of an axis with a certain L<role|Graphics::Toolkit::Color::Manual::Space/FAMILY>.
L</lighten>, L</darken> and L</lightness> need a I<lightness> axis (present in 
L<LAB|Graphics::Toolkit::Color::Manual::Space/LAB-family> and 
L<HSL|Graphics::Toolkit::Color::Manual::Space/HSL-family> spaces)
and L</saturate>, L</desaturate> and L</saturation> need a I<saturation> axis
(present in L<HSL|Graphics::Toolkit::Color::Manual::Space/HSL-family> and 
L<HSV|Graphics::Toolkit::Color::Manual::Space/HSV-family> spaces). 

C<raw> defaults to false (0), which allows the method to clamp the color 
values into an acceptable range before delivering the result. Set C<raw> to 1 in order
to get the unaltered result that might be less useful and cause issues later.

=head2 lighten 

C<lighten> produces a color that is brighter than the given one, as long as the argument
is positive ( &gt; 0). It simply adds to the lightness value (0..1) of the calling color the given number.
Let's assume the given color (caller) is a mid blue, which has a
lightness of .46 (46% of the maximum I<lightness>). Calling:

  $midblue->lighten( 0.13 );                                # brighter color than $midblue
  $midblue->lighten( by => 0.13 );                          # same result
  $midblue->lighten( by => 0.13, in => 'OKHSL' );           # also the same
  $midblue->lighten( by => 0.13, in => 'OKHSL', raw => 0 ); # no change yet

produces a color with same blue tone but with a lightness that is .46 + .13 = 0.59 (59%).
A lightness of 0 means black and 1 is white. If the resulting lightness would be below 0
or above 1 it will be clamped into range
(it can not exceed I<black> or I<white> if C<raw> is set to false, which is the default).
If C<raw> is set to true the lightness value of the color can exceed the 0 .. 1 range.
This might have an informal value but can not be displayed correctly.
The operation can only be done C<in> a color space with an axis that can fulfill the I<lightness> role.

  $midblue->lighten( -0.13 );                               # darker color
  $midblue->lighten( -1 );                                  # always black
  $midblue->lighten( by => -0.13, raw => 1 );               # might get darker than black
  $midblue->lighten( by =>  0.13, in => 'RGB' );            # error, since RGB has no lightness axis

=head2 darken

C<darken> works exactly like L</lighten>, just in the opposite direction (subtracting instead of
adding to the I<lightness>).
It produces a darker color unless a negative value is passed via the positional argument
or the named argument C<by>. This method (like C<lighten>) is not strictly necessary,
but helps API expressivity and is standard in many color libs.

  $midblue->darken( -0.13 );                        # same as $midblue->lighten( 0.13 );

=head2 saturate

C<saturate> produces a more saturated, colorful, vibrant color. If the given amount is negative,
the satuation is decreased toward a colorless grey tone. As with L</lighten>, the value provided
as the C<by> argument (default) will be added on an absolute scale that gets clamped into range (0 .. 1),
unless C<raw> is manually set to 1 (true).
This operation can only be done C<in> a color space with an axis that can fulfill the I<saturation> role.

  $midblue->saturate( 0.13);                        # saturate in OKHSL
  $midblue->saturate( by => 0.13);                  # saturate in OKHSL
  $midblue->saturate( by => 0.13, in => 'HSL' );    # saturate in HSL, different result

=head2 desaturate

C<desaturate> is the antagonist of L</saturate> like C<darken> is the
opposite of C<lighten>. It also understands the arguments C<by> (default), C<raw> and C<in>.

  $midblue->desaturate( by => -0.13, in => 'HSL' ); # same as above
  $midblue->desaturate( by => -0.13, in => 'RGB' ); # error, since RGB has no saturation axis

=head2 tint

C<tint> produces a color that is a mix between the current color and white (#FFFFFF),
which has increased lightness and decreased saturation.
The argument C<by> (default) states how much white (in %) is in the mix.
By default values above 1 have the same result as 1 (100 %): a pure white.
Values of zero will return the same color as the calling object holds.
Values below zero will have same effect as L</shade> (with a positive value).
Please note that unlike methods that set a different lightness or saturation directly,
C<tint> will work in any color space.

  $midblue->tint( 0.13 );                           # 13% white, 87% midblue
  $midblue->tint( by => 0.13, in => 'OKHSL', raw => 0 ); # same call, same result
  $midblue->tint( by => 0.13, in => 'RGB' );        # slightly different result
  $midblue->tint( by => 1.13, raw => 1 );           # imaginary ultra white
  $midblue->tint( -1 );                             # black

If you imagine a line in a color space of your choice between the given color
and white, you can give each position between those points a number between zero and one.
Of course you could also extend the line beyond the two points and keep on counting
below zero and above one, which very well might be outside the boundaries of the chosen space.
In order get those positions (colors) as result you have to set the C<raw> argument to one (true).

=head2 tone

C<tone> produces a color that is a mix between the current color and mid grey,
a 1:1 mix between white and black. The result has decreased saturation but can be
lighter or darker depending on if the current color is darker or lighter than mid grey.
Other than that it works exactly like L</tint>.

  $midblue->tone( 0.13 );                           # greyish blue
  $midblue->tone( by => 0.13, in => 'OKHSL', raw => 0 ); # filling in the defaults
  $midblue->tone( by => 0.13, in => 'RGB' );        # different greyish blue
  $midblue->tone( 1 );                              # mid grey
  $midblue->tone( by => 1.13 );                     # light yellow

=head2 shade

C<shade> produces a color that is a mix between the current color and black (#000000).
The new color has decreased lightness and decreased saturation.
Per default values above 1 have the same result as 1: a full black and values of zero
and below will return the same color as the calling object holds
(unless C<raw> is set to 1). Beside that all arguments work like in L</tint>.

  $midblue->shade( 0.13 );                          # darker blue
  $midblue->shade( by => 0.13, in => 'OKHSL', raw => 0 ); # same but explicit
  $midblue->shade( by => 0.13, in => 'RGB' );       # different darker blue
  $midblue->shade( by => 1.13, raw => 1 );          # imaginary ultra black

=head2 lightness

C<lightness> produces a color with a specific I<lightness> (brightness) but same I<hue>
and I<saturation> as the caller (invocant) has. It can substitute the methods L<lighten> and L<darken>,
since it also listens to the arguments C<in>, C<raw> and C<by>, which work exactly the same way as with
L<lighten>. Only here C<by> has also the alias C<add> since it just adds to the I<lightness> value.
In the same way C<multiply> (alias C<x>) multiplies the lightness value with a given factor and
<set> just sets the I<lightness> to the value provided (0..1). <set> is also the default argument, so
a single, positional argument will be interpretet as a number the new lightness will be set to.
<set>, C<multiply> and C<add> will be applied in this order and you have to use at least one them.

  $midblue->lightness( 0.13 );                      # blue, with a lightness of 13%
  $midblue->lightness( set => 0.13, raw => 0, in => 'OKHSL' ); # same result
  $midblue->lightness( set => 0.13, x => 2 );       # blue, with a lightness of 26% =  2 * 13%
  $midblue->lightness( set => 0.13, add => .1 );    # blue, with a lightness of 23% = 10 + 13%
  $midblue->lightness( set => 0.13, in => 'CMY' );  # error: CMY has no axis with a lightness role
  $midblue->lightness( multiply => 1.5 );           # blue, with a lightness of 69% = 1.5 * 46% (mid blue)
  $midblue->lightness( multiply => 5 );             # white (clamped at 100% lightness)
  $midblue->lightness( multiply => 5, raw => 1 );   # 46% * 5 = 230% lightness (virtual color)


=head2 saturation

C<saturation> produces a color with a specific I<saturation> (colorfulness, vibrancy) but same I<hue> and
I<lightness> as the caller (invocant) has. It can substitute the methods L</saturate> and L</desaturate>,
since it also listens to the arguments C<in>, C<raw> and C<by>, which work exactly the same way as with
L</saturate>. You may have noticed, it completely mirrors the L</lightness> method with all arguments
(C<set>, C<multiply>, C<add>) and their behaviour .
The only difference is, their applied to the I<saturation> value and not on the I<lightness> axis.
Logically it can only calculated C<in> a color space which has an axis with a I<saturation> role.

  $midblue->saturation( 0.13 );                     # blue, with a saturation of 13%
  $midblue->saturation( set => 0.13, raw => 0, in => 'OKHSL' ); # same result
  $midblue->saturation( set => 0.13, x => 2 );      # blue, with a saturation of 26%
  $midblue->saturation( set => 0.13, in => 'CMY' ); # error: CMY has no axis with a saturation role
  $midblue->saturation( multiply => 1.5 );          # blue, with a saturation of 20% * 1.5 = 35%
  $midblue->saturation( multiply => 0 );            # grey (0% saturation)
  $midblue->saturation( multiply => 7 );            # pure blue (clamped at 100% saturation)
  $midblue->saturation( multiply => 5, raw => 1 );  # 20% * 6 = 120% saturation (virtual color)

  
=head2 derive

C<derive> lets you calculate any color based on basic math (C<set>, C<multiply> and C<add>
- applied in that order) and the values of the given color. You have to use at least one of
these three arguments. In this regard it works similar to L</lightness> and L</saturation>,
but in any color space and on any axis. That is why these arguments do not accept numbers but
a HASH references with numbers as values. The keys have to be axis names of one color space.
It is enough to provide at least one axis name, but if the space name can not securely deduced,
it is better to request the color space in which the operations are calculated explicitly
via the argument C<in>. If the given axis names originate from different spaces or not from
the requested space, an L<error|Graphics::Toolkit::Color::Manual::Error> might get thrown.

The other difference to the methods L</lightness> and L</saturation> is the argument C<range>,
which lets you hand pick the value range for each axis. L</lightness> and L</saturation> did not need that,
since they operate only on normal values (0..1). Please note that the selected value ranges
are only in effct during the calculation of the method result and are independant from value ranges
of the input (C<new>) or output (C<values>). If no ranges are set,
the default ranges of the selected or deduced space are in effect.

  my $color = color( 20, 0, 40 );                   # new color from RGB (red, green, blue) values
  my $c = $color->derive( set => {red => 30} );     # same as $c = color(30, 0, 40); 
  my $c = $color->derive( multiply => {r => 2} );   # same as $c = color(40, 0, 40); # 40 = 20 * 2
  my $c = $color->derive( add => {red => 30} );     # same as $c = color(50, 0, 40); # 50 = 20 + 30
  # set green to max value: which is 1 in normal range (0..1) and 255 in RGB default range (0..255)
  $color->derive( set => {green => 1}, range => 'normal' );  # same as color(20, 255, 40);
  # blue = 60 = (20 * 2) + 20
  $color->derive( set => {b => 20}, multiply => {b => 2}, add => {b => 20});  # same as color(20, 0, 60);
  $color->derive( set => {cyan => 1});              # set red to 0 in CMY, same as color( 0, 0, 40);
  $color->derive( add => {hue => 20}, in => 'HSL'); # color with hue of 340 = 320 + 20 (deep purple)


=head2 invert

C<invert> computes a new color, where all or some values are inverted 
according to the ranges of the chosen color space. To invert means in
a Euclidean space that the value has after the operation the same
absolute difference to the maximal value as it had before the operation to
the minimal value. On an angular axis it is a rotation of 180 degrees,
which means adding half the maximum. The method accepts three named 
arguments: C<only>, C<raw> and C<in>. The first one can be provided as a 
positional argument if it is the only one (default argument).

L<only|Graphics::Toolkit::Color::Manual::Argument/only> restricts the
operation to the axes named by C<only> (long or short axis name). 
You may provide several axis names within an ARRAY reference, as long
they belong to one color space. The default is to invert all values of a color.

L<raw|Graphics::Toolkit::Color::Manual::Argument/raw> defaults to false,
which allows C<invert> to clamp values into range. C<invert> can only create
out of range colors if C<raw> is set to true(1) and the input (given color)
is already out of range.

L<in|Graphics::Toolkit::Color::Manual::Argument/in> sets the color space
the values will be inverted in, which is per default I<OKHSL>. But please
note that the method tries to get hints from the C<only> argument in order
to determine the color space. There will be an 
L<error|Graphics::Toolkit::Color::Manual::Error>
if the axis names provided by C<only> do not match the space given by C<in>.

    my $black = $white->invert();                      # to state the obvious
    my $gray = $gray50->invert();                      # changed nothing
    my $blue = $yellow->invert( in => 'LUV' );         # invert in LUV space
    $color->invert( 'red' );                           # invert only red value
    $color->invert( only => 'red' );                   # same but explicit
    $yellow->invert( in => 'HSL', only => 'hue' );     # same result as $yellow->complement();
    $yellow->invert( in => 'HSL', only => [qw/s l/] ); # invert only saturation and lightness
    $yellow->derive( x=> {s=>-1, l=>-1}, add=> {s=>1, l=>1}, in=> 'HSL', range=> 1 ); # same result

=head2 apply

C<apply> calculates a gamma correction, which is just a power function on
normalized color values (range 0 .. 1). Gamma is in this context the name 
of a variable that contains the power. (C<$value = $value ** $gamma;>)
The method expects two named arguments: C<gamma> and C<in>. The first one
is required and second one is optional. There is no rule that allows for
a lone positional argument.

C<gamma> has to be either a floating point number or a HASH reference
that contains a gamma value per axis. Long or short axis names can be used
as keys. A gamma correction is reversed with the same function, 
just with an inverted gamma value (C<1 / $gamma>). Even if some 
implementations apply the inverted gamma, GTC uses the gamma value as given,
to not further complicate things because there is no I<'invert'> argument.
Just prepend the C<gamma> with C<< 1 / >>.

L<in|Graphics::Toolkit::Color::Manual::Argument/in> sets the color space
the values will be first converted to. Then these values will be normalized,
before the gamma value is applied. C<in> defaults to 
L<LinearRGB|Graphics::Toolkit::Color::Manual::Space/LinearRGB>
since this is the default IO space with gamma removed, ready for a custom
gamma correction. Applying gamma makes only sense in Euclidean spaces 
with the origin in one corner of the space like I<RGB> or I<CIEXYZ>.
These are with minor exceptions only the spaces from the 
L<RGB|Graphics::Toolkit::Color::Manual::Space/RGB> family, since even 
I<LAB> type spaces do not fit. They are Euclidean, but their origin is not
in one corner but the center of one face.

    my $linear_blue = $blue->apply( gamma => 2.2 );         # is the same as :
    my $linear_blue = $blue->apply( gamma => {r => 2.2, g =>2.2, b => 2.2}, in => 'LinearRGB' );



=head2 mix

C<mix> creates a new color, that has the average values between the calling
object and another color (or several colors). It accepts four named
arguments: C<to>, C<by>, C<raw> and C<in>, but only the first one is required 
and can be also provided as the only positional argument. For compatibility
C<amount> can be used as an alias for C<by>.

The L<to|Graphics::Toolkit::Color::Manual::Argument/to> argument works 
like in other methods, with the exception that it also accepts an ARRAY
ref (square brackets) with several color definitions or GTC color objects.

L<by|Graphics::Toolkit::Color::Manual::Argument/by> designates the mix amount
of the other color(s) (C<to>) in percent.
A value of 0.2 means that the other color or any of the other colors gets 20%.
The calling color receives whatever is left percentage wise, which might be nothing. 
Per default C<mix> computes a 50-50 (1:1 or 0.5-0.5) mix between all involved colors.
If C<to> has several colors assigned, then also C<by> might receive an ARRAY
reference with several percentage values that have to be provided in the same
order as the colors. If the sum of the percentage values exceeds one (100%)
then only the ratio between the other colors gets preserved and the caller
gets overlooked.

L<raw|Graphics::Toolkit::Color::Manual::Argument/raw> defaults to false,
which allows C<mix> to clamp the result values into range. C<mix> can 
only create an out of range color if some of the input color(s) are 
already out of range.

L<in|Graphics::Toolkit::Color::Manual::Argument/in> sets the color space
the values will be mixed in, which is per default I<OKLAB>.


    $blue->mix( $silver );                                     # 50% silver, 50% blue
    $blue->mix( to => 'silver',           by =>  .6 );         # 60% silver, 40% blue
    $blue->mix( to => [qw/silver green/], by => [.1, .2]);     # 10% silver, 20% green, 70% blue
    $blue->mix( to => [qw/silver green/], by => [.3, .9]);     # 25% silver, 75% green,  0% blue
    $blue->mix( to => [qw/silver green/], by =>  .3);          # 30% silver, 30% green, 40% blue
    $blue->mix( to => [qw/silver green/] );                    # 33% silver, 33% green, 33% blue
    $blue->mix( to => {H => 120, S =>100, L => 50}, in => 'HSV' ); # teal =  50% green, 50% blue
    # the other color in the last example was defined in HSL but mixed in HSV
